GPO: Google Chrome and Mozilla Firefox, templates, home page, extensions, password manager, PAC proxy, default browser and chrome://policy showing an error

The Chrome Enterprise bundle ADMX files and the Firefox templates (or its policies.json), home page, allowed, blocked and force-installed extensions, the password manager off, a PAC file for every browser, the associations XML for the default browser, and what to do when chrome://policy marks a policy as error or not applied.

Level 2 · GPO: drives, printers and preferences · 8 min read · Updated 6 Nov 2026

Rather practise it?Solve the simulated ticket "Chrome ignores the extension list" in SysAdmin Desks ↗

What you'll get

Managing Chrome and Firefox with the same GPO and the same approach as Edge: the company home page, only approved extensions, no passwords saved in the browser, the same proxy for all of them and the default browser you decide on. And knowing how to read chrome://policy and about:policies when a policy does not do what it should.

Before you start

  • The template central store created in SYSVOL. The ADMX templates, Edge and Microsoft 365 Apps guide explains it, along with the Edge configuration, which is not repeated here.
  • Downloaded: the Chrome Enterprise Bundle (which includes the policy templates) and the Firefox policy templates Mozilla publishes in its policy-templates repository.
  • Chrome and Firefox installed on the computers (each vendor's MSI; with MECM or Software Installation).
  • A pilot OU: OU=Piloto,OU=Equipos,DC=contoso,DC=local, and the PAC file published on an internal web server.

1. The templates in the central store

BrowserFilesShown in the editor as
Chromechrome.admx, google.admx (+ GoogleUpdate.admx for updates)Google › Google Chrome and Google Chrome - Default Settings (users can override)
Firefoxfirefox.admx, mozilla.admxMozilla › Firefox

Each .admx with its .adml for es-ES and en-US, like any other template:

  • Chrome stores its policies in HKLM\SOFTWARE\Policies\Google\Chrome (or HKCU if they are per user); Firefox, in HKLM\SOFTWARE\Policies\Mozilla\Firefox.
  • Firefox also accepts a policies.json file in C:\Program Files\Mozilla Firefox\distribution\, with the same names. It is useful for computers outside the domain or to include in the installation package. If a policy is set in both places, the GPO wins.
  • The templates change with each major browser release: an old ADMX does not show new policies and still shows retired names.

The GPOs are computer GPOs: CMP-Chrome and CMP-Firefox, linked first to the pilot OU.

In Firefox the policy is Homepage, under Mozilla › Firefox › Home page. In policies.json:

Locked stops the user changing it; without it, it is just a starting value.

3. Extensions: allowed, blocked and force-installed

The same scheme as in Edge: everything blocked except what is approved, and the essentials force-installed.

Chrome, under Google Chrome › Extensions:

  • Configure extension installation blocklist (ExtensionInstallBlocklist): *.
  • Configure extension installation allow list (ExtensionInstallAllowlist): the 32-letter ID of each approved extension, shown at the end of its Chrome Web Store URL.
  • Configure the list of force-installed apps and extensions (ExtensionInstallForcelist): <id>;https://clients2.google.com/service/update2/crx, the Chrome Web Store update address.

For finer cases there is ExtensionSettings, which goes on a single line of JSON and takes precedence over the three above.

Firefox uses ExtensionSettings (Mozilla › Firefox › Extensions › Extension Management), also in JSON, with the extension ID (email-style or a GUID, shown in about:support) and its addons.mozilla.org address:

An extension that is not in the store (an internal .crx or .xpi) can only be force-installed in Chrome if the computer is domain-joined or managed. On standalone computers, Chrome ignores it.

4. The password manager, off

Company passwords belong in the corporate password manager, not the browser:

  • Chrome: Google Chrome › Password manager › Enable saving passwords to the password manager (PasswordManagerEnabled) = Disabled. The user can no longer save new passwords; the ones they had stay until they delete them.
  • Firefox: PasswordManagerEnabled = false (and OfferToSaveLogins = false), under Mozilla › Firefox.
  • So they stop asking to be the default all the time: DefaultBrowserSettingEnabled = Disabled in Chrome and DontCheckDefaultBrowser = true in Firefox.

5. A PAC proxy for every browser

A PAC file decides what goes through the proxy and what goes direct, and it is the same for everyone:

It is served with the MIME type application/x-ns-proxy-autoconfig. Three layers to apply it:

  1. Windows (Edge, Chrome by default, Office and most programs): the AutoConfigURL value in HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings, with a Registry preference in a user GPO. Firefox also uses this system setting by default.
  2. Chrome, locked: Google Chrome › Proxy server › Choose how to specify proxy server settings (ProxyMode) = Use a .pac proxy script and ProxyPacUrl = the PAC URL. Edge has the same two policies with the same names.
  3. Firefox, locked: the Proxy policy:

ImportEnterpriseRoots makes Firefox trust the certificate authorities in the Windows store, essential if the proxy inspects HTTPS with a certificate from the internal CA.

Windows services (Windows Update, agents) use none of this: they go through WinHTTP, configured separately. The network diagnosis on Windows 11 guide shows how to check it with netsh winhttp.

6. The default browser: the associations XML

Windows 11 does not let a program make itself the default; with GPO you do it with an associations file:

  1. On a reference computer, choose Chrome as the default for http, https, .htm and .html and export: Dism /Online /Export-DefaultAppAssociations:D:\Asociaciones.xml.
  2. Keep only the browser lines in the XML:

For Firefox, ProgId="FirefoxURL-308046B0AF4A39CB" for http and https, and FirefoxHTML-308046B0AF4A39CB for .htm and .html (the final part depends on the install folder: always take it from the exported XML).

  1. Copy the XML to a path every computer can read, such as \\contoso.local\NETLOGON\Asociaciones.xml, and in a computer GPO: Computer Configuration › Administrative Templates › Windows Components › File Explorer › Set a default associations configuration file = Enabled with that path.

It applies at sign-in, so you need to sign out to see it.

7. The ticket: "chrome://policy marks the policy as an error" or "it is not applied"

Tuesday, 10:00. In the pilot, Edge and Firefox open the intranet at startup; Chrome does not. On PC-0533, chrome://policy shows HomepageLocation with status OK and ExtensionSettings with status Error; on a pilot laptop, the home page appears as not applied.

  1. Reload and read every column: in chrome://policy, Reload policies after gpupdate /force. Each row shows the value, the source (Platform is the GPO), whether it is machine or user, the level (mandatory or recommended) and the status. Clicking Show more reveals the error message.
  2. If Chrome does not show the policy, it has not reached it: gpresult /scope computer /r to see whether the GPO applies and, in the registry:
  1. **The most common reasons for Error or *Ignored***:
  • Malformed JSON: ExtensionSettings was pasted into the editor with line breaks and Chrome only received the first line. It goes on a single line, validated beforehand. That is the PC-0533 case.
  • Conflict: the warning that more than one source has different values. A user GPO and a computer GPO, or the GPO and Chrome's cloud management. The machine one wins; leave the policy in one place only.
  • Deprecated policy: names such as ExtensionInstallBlacklist, from old templates, are flagged as deprecated. Update the ADMX files and set the new name (ExtensionInstallBlocklist).
  • Unmanaged computer: on Windows, some policies (such as the home page or force-installing extensions from outside the store) only apply if the computer is domain-joined, MDM-managed or enrolled in Chrome's cloud management. The pilot laptop had been left out of the domain after a reinstall: the policy reached it through a .reg file, not a GPO.
  1. Firefox, the same: about:policies has an Errors tab that says which policy and why (a misspelt name, invalid JSON in policies.json).

In the ticket: the policy, its status and message in chrome://policy, the cause (JSON on several lines), the change and the check: status OK on the five pilot computers.
