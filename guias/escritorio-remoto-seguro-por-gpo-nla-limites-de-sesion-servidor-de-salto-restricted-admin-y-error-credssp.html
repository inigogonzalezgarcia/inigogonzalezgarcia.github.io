Guides · Level 3

Secure Remote Desktop by GPO: who can sign in, NLA and TLS, session limits, admin networks only, jump host, Restricted Admin and Remote Credential Guard, and the NLA or CredSSP error

Enabling RDP only where it is needed, deciding who gets in with groups and user rights, requiring NLA and TLS, ending idle and disconnected sessions, limiting port 3389 to the admin network, reaching servers from a jump host with Restricted Admin or Remote Credential Guard, and fixing the NLA and CredSSP errors.

Level 3 · Security GPOs · 7 min read · Updated 6 Nov 2026

What you'll get

Remote Desktop configured the same way on every server and computer from GPO: on only where it is used, who can sign in decided by AD groups, authentication before the session opens, forgotten sessions ending on their own, port 3389 open only to the admin network, and admins coming in from a jump host without leaving their credential on each server. And what to do with the two most common connection errors.

Before you start

  • GPMC and permissions on the server and computer OUs.
  • The baseline security GPOs applied or in pilot: Credential Guard and LAPS fit with what is done here.
  • A defined admin network, for example 10.10.50.0/24, and a jump host (srv-jump01, 10.10.50.10) that admins connect to.
  • One AD group per set of servers and who gets into them: GG-RDP-SRV-Finance, GG-RDP-SRV-Applications.

1. Turn RDP on and decide who gets in

In Computer Configuration › Policies › Administrative Templates › Windows Components › Remote Desktop Services › Remote Desktop Session Host › Connections, Allow users to connect remotely by using Remote Desktop Services = Enabled in the server GPO. On workstations, only if support connects that way; otherwise Disabled.

Signing in over RDP needs two things: the right Allow log on through Remote Desktop Services (by default Administrators and Remote Desktop Users have it) and not being in the deny right, which always wins.

  • Local group membership, with preferences: Computer Configuration › Preferences › Control Panel Settings › Local Users and Groups › New › Local Group, group Remote Desktop Users (built-in), action Update, member CONTOSO\GG-RDP-SRV-Finance. Update adds without removing what is there; the Restricted Groups policy replaces everything.
  • In Security Settings › Local Policies › User Rights Assignment › Deny log on through Remote Desktop Services: Local account (S-1-5-113; the local admin signs in at the console or with LAPS, not over RDP from the network) and, on member servers and workstations, Domain Admins: those accounts only sign in on domain controllers.

If someone without the right tries to sign in, the session drops after the password with The connection was denied because the user account is not authorized for remote login. It is a group problem, not a network one.

2. NLA, TLS and encryption

In Remote Desktop Session Host › Security:

  • Require user authentication for remote connections by using Network Level Authentication = Enabled. With NLA the user authenticates (through CredSSP) before the server creates the session and draws the sign-in screen: without a valid account there is no session using resources and no screen to attack.
  • Require use of specific security layer for remote (RDP) connections = Enabled, layer SSL (it is TLS).
  • Set client connection encryption level = High Level.
  • Optional, with an internal CA: Server authentication certificate template with the name of a certificate template for RDP. The server requests its certificate and the "identity of the remote computer cannot be verified" warning goes away.

3. Idle and disconnected sessions

A disconnected session is still open: processes, locked files and, without Credential Guard, the credential in memory. In Remote Desktop Session Host › Session Time Limits:

PolicyUsual value on servers
Set time limit for active but idle Remote Desktop Services sessions1 hour
Set time limit for disconnected sessions1 hour
End session when time limits are reachedEnabled

And in Connections, Restrict Remote Desktop Services users to a single Remote Desktop Services session = Enabled. In Device and Resource Redirection, on sensitive servers, Do not allow drive redirection and Do not allow Clipboard redirection: without them, copying files from the server to the laptop is drag and drop.

Times are stored in milliseconds: 3600000 is one hour.

4. Only from the admin network

RDP requiring NLA is not enough if any office PC can reach port 3389 on a server. In the server firewall GPO, the predefined rules of the Remote Desktop group (Remote Desktop - User Mode (TCP-In) and (UDP-In), port 3389) with Scope › Remote IP address = the jump host IPs, 10.10.50.10 and 10.10.50.11.

@FirewallAPI.dll,-28752 is the internal name of the Remote Desktop group, the same in any language. If the GPO does not contain those rules yet, add them first as Predefined from the editor. Profiles, merging with local rules and dropped-packet logging are in the Windows Firewall by GPO guide.

5. Jump host, Restricted Admin and Remote Credential Guard

With normal RDP, your password travels to the server and stays in its memory: if that server is compromised, so is your admin account. Two modes avoid it:

Restricted AdminRemote Credential Guard
What reaches the serverNothing reusableNothing: Kerberos is redirected back to the source device
Network resources from the sessionAs the computer accountAs you
RequirementsBeing an admin on the serverKerberos (connect by name, not IP), same or trusted domain
Typical useSupport connecting to user devicesAdmins from the jump host

On the target servers and devices: Administrative Templates › System › Credentials Delegation › Remote host allows delegation of non-exportable credentials = Enabled. Without it, neither mode works.

On the jump host and admin workstations: System › Credentials Delegation › Restrict delegation of credentials to remote servers = Enabled, with Require Remote Credential Guard or Restrict Credential Delegation (uses Remote Credential Guard and, if it cannot, Restricted Admin). By hand: mstsc /remoteGuard or mstsc /restrictedAdmin.

For support connecting to user devices, Microsoft recommends Restricted Admin rather than Remote Credential Guard: if the user's device is compromised, with Remote Credential Guard the attacker could use the open channel to request access in your name while the session lasts.

On the server, event 4624 with logon type 10 shows Restricted Admin Mode: Yes when the session came in that way.

6. The ticket: "it says it requires Network Level Authentication" or "CredSSP"

Case 1. An admin tries to get into SRV-APP07 and gets: The remote computer that you are trying to connect to requires Network Level Authentication (NLA), but your Windows domain controller cannot be contacted to perform NLA. With NLA, the server must validate the credential against a DC before opening the session.

  1. From the jump host, Test-NetConnection SRV-APP07 -Port 3389: it answers, so it is not the firewall.
  2. On the hypervisor console or iDRAC/iLO, with the local admin (LAPS password): Test-ComputerSecureChannel returns False. The server was restored from an old backup and its computer account password no longer matches AD.
  3. Test-ComputerSecureChannel -Repair -Credential CONTOSO\adm.lgarcia returns True; RDP works again without touching NLA.

If the message is The Local Security Authority cannot be contacted... This could be due to an expired password, the user's password has expired or is flagged to change at next sign-in: with NLA there is no screen to change it. Change it from another device (Ctrl+Alt+Del › Change a password) or from support, and try again.

Case 2. From an up-to-date laptop to SRV-LEG01, an old server restored from an unpatched template: An authentication error has occurred. The function requested is not supported... This could be due to CredSSP encryption oracle remediation. The client, with the default setting (Mitigated), refuses to fall back to the server's vulnerable CredSSP version.

  • The fix is updating and restarting the server. Afterwards, the GPO Credentials Delegation › Encryption Oracle Remediation = Force Updated Clients on servers, so they do not accept unpatched clients either.
  • Setting Vulnerable on a client is a temporary workaround on a single device with a removal date, never by GPO for everyone. Turning NLA off on the server is not the fix either.

In the ticket: exact message, cause (broken secure channel, expired password or missing patch), what was changed and the successful connection from the jump host.
