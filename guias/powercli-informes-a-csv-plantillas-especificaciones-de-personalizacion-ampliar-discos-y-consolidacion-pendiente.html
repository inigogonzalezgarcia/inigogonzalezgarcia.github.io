PowerCLI for operations: CSV reports, templates, customization specs with a static IP, growing disks and a VM that needs consolidation

Installing VCF.PowerCLI and connecting without ignoring the certificate, four weekly CSV reports (old snapshots, VMware Tools, datastore space and VMs per host), templates that get patched, Windows and Linux customization specs with a static IP, growing the disk of a Windows VM and of a Linux VM with LVM, and the VM that needs consolidation and whose disk will not grow.

Level 3 · VMware vSphere and vCenter · 12 min read · Updated 6 Nov 2026

What you'll get

Using PowerCLI as an operations tool rather than for one-off commands: a weekly CSV report anyone can open in Excel, templates that stay patched, Windows and Linux customization specs that leave the VM with its static IP and its name, and the complete procedure to grow a disk, from vCenter down to the file system. And what to do when vCenter warns Virtual machine disks consolidation is needed and the disk you have been asked to grow refuses to change.

Before you start

  • PowerShell 7.4 or later (or Windows PowerShell 5.1) on the admin workstation or on a jump server with access to vCenter on 443.
  • A vCenter account with a custom role for changes and another read-only one (Read-only role, propagated from the root) for scheduled reports. Day-to-day work in the console (creating VMs, snapshots, hosts in maintenance) is in the vSphere and vCenter guide; this one starts from there.
  • VMware Tools in the VMs (on Linux, the distribution's open-vm-tools package): without them there is no IP in the inventory, no customization and no clean shutdown.

1. Installing PowerCLI and connecting without ignoring the certificate

Since version 9.0 the module is published as VCF.PowerCLI; the cmdlets are the same as in VMware.PowerCLI 13 and scripts keep working. If the machine has the old module, remove it first so versions do not mix:

  • -InvalidCertificateAction Fail forces you to really trust vCenter. On the vCenter landing page, Download trusted root CA certificates downloads download.zip; the certificate in the certs\win\ folder goes into the computer's Trusted Root Certification Authorities (or by GPO to every admin workstation). Ignore stays in the lab.
  • For scheduled tasks, the credential is saved once with the account that will run the task: Get-Credential CONTOSO\svc-vc-informes | Export-Clixml C:\Scripts\vc-ro.xml. The file is encrypted with DPAPI: only that account, on that machine, can read it.

2. Four weekly CSV reports

A D:\Scripts\Informe-vSphere.ps1 script with four blocks, each with its own file. -Delimiter ';' and -Encoding utf8BOM make a Spanish-locale Excel open the columns and accents correctly first time.

How to read each one:

  • Snapshots: the Days column is what goes to the weekly meeting; the 72-hour rule is in the vSphere and vCenter guide.
  • VMware Tools: guestToolsNeedUpgrade is an old version (update it in the next window, with Update-Tools -NoReboot or from Lifecycle Manager); guestToolsUnmanaged is normal with open-vm-tools on Linux, which is updated with the distribution's packages; guestToolsNotInstalled or a guestToolsNotRunning state on a powered-on VM mean vCenter cannot see its IP or shut it down cleanly.
  • Datastores: ProvisionedGB larger than CapacityGB is overcommitment with thin disks. It is acceptable while there is headroom and someone watches it; the day the VMs fill what was promised, the datastore runs out of space and the VMs pause.
  • Hosts: more than 4 powered-on vCPUs per physical core, or a host with twice as many VMs as the others (DRS in manual, a forgotten affinity rule), show up here before they show up in performance.

The scheduled task runs pwsh.exe -NoProfile -File D:\Scripts\Informe-vSphere.ps1 on Mondays at 7:00 with the CONTOSO\svc-vc-informes account, and the files land in a team share.

With thousands of VMs, Get-VM per host is slow. Get-View -ViewType VirtualMachine -Property Name,Runtime.Host,Guest brings just those properties and takes seconds.

3. Templates: keeping them patched

A template nobody touches for a year creates VMs with a year of pending patches. The cycle, once a month, is to turn it into a VM, update it and turn it back into a template:

  • Linux: empty /etc/machine-id before converting. Otherwise every cloned VM shares the identifier and the DHCP server may give them the same IP. If the template uses cloud-init, sudo cloud-init clean as well.
  • Windows: Sysprep is not run by hand; the customization spec runs it on every deployment and changes the SID. What you do is install the cumulative updates and reboot until none are pending, or the first boot of every new VM takes half an hour.
  • With several vCenters, a subscribed Content Library distributes the same template to all of them; the update cycle is the same.

4. Customization specs with a static IP

The customization spec tells vCenter what to change inside the guest OS when cloning: name, domain, DNS, network. You create one per OS type:

  • -NamingScheme Vm: the computer name is the VM name. One name that matches in vCenter, DNS and Active Directory.
  • -TimeZone 105 is Romance Standard Time (Madrid, Paris).
  • The domain join account, with delegated rights only to create computers in the servers OU, not a domain admin.

To give each deployment a static IP you do not create a spec per VM: you clone the base one as non-persistent (it lives only in the session) and change its NIC:

In a Windows spec, DNS goes on the NIC itself: Set-OSCustomizationNicMapping ... -Dns 10.20.0.10,10.20.0.11.

If the event is CustomizationFailed or never arrives, the log is inside the VM: /var/log/vmware-imc/toolsDeployPkg.log on Linux and C:\Windows\Temp\vmware-imc\guestcust.log on Windows (plus the Sysprep logs in C:\Windows\Panther\). The usual causes: open-vm-tools missing from the template, a distribution the vCenter version does not recognise, or a domain join account with an expired password.

5. Growing a disk: the VM first, then the OS

First of all: the VM must have no snapshots and the datastore must have the space. Then, the VM's disk:

On Windows, rescan the disk and extend the partition to the maximum:

On Linux with LVM (Ubuntu Server's default install) it is four steps: make the kernel see the new size, grow the partition, the physical volume and the logical volume with its file system:

  • growpart is in the cloud-guest-utils package (Ubuntu) or cloud-utils-growpart (RHEL).
  • lvextend -r also grows the file system, whether ext4 (Ubuntu) or XFS (RHEL, with the rhel/root volume). XFS grows but does not shrink: ask for the right size.
  • For data, it is often cleaner to add a new disk (New-HardDisk -VM srv-web-04 -CapacityGB 100 -StorageFormat Thin) and mount it separately than to grow the system disk.

6. The ticket: "srv-erp-01 needs consolidation and disk E: cannot be grown"

Tuesday, 11:00. The ERP team asks for 200 GB more on disk E: of srv-erp-01. Set-HardDisk fails, in the vSphere Client the disk size is locked and the VM has a yellow warning: Virtual machine disks consolidation is needed.

  1. Which VMs are like this: Get-VM | Where-Object { $_.ExtensionData.Runtime.ConsolidationNeeded } | Select-Object Name. Out comes srv-erp-01.
  2. Snapshots you cannot see: Get-Snapshot -VM srv-erp-01 returns nothing, but Get-HardDisk -VM srv-erp-01 | Select-Object Name, Filename shows srv-erp-01_1-000002.vmdk. The VM is writing to the delta disk of a snapshot that no longer appears in the snapshot manager. While that delta exists, the disk cannot be grown.
  3. Why: last night's backup. The backup proxy in hot-add mode mounts the VM's disks to read them and, if the job is interrupted, keeps them. Check on the proxy:

Remove-HardDisk without -DeletePermanently only removes the disk from the proxy's configuration. With that parameter you would delete the ERP's disk. Check the Filename twice before pressing Enter.

  1. Consolidate, outside working hours if the VM writes a lot (at the end of consolidation the VM freezes for an instant):

If the task fails with Unable to access file ... since it is locked, someone still has the disk open: another proxy, a backup job in progress or a host that keeps the lock. The task error in vCenter says which file.

  1. Grow it: with no delta, Set-HardDisk works and the rest is step 5.

Other reasons a disk "will not grow":

SymptomCauseWhat to do
The disk size cannot be editedThere is a snapshot or a pending deltaDelete the snapshot or consolidate
The VM has the new size and Windows does notThe disk is MBR and goes past 2 TBNew GPT disk and move the data
Extend Volume is greyed out on C:A recovery partition right after C:Move or recreate the recovery partition, in a window and with a backup
lsblk still shows the old sizeThe disk rescan is missingThe echo 1 > .../rescan from step 5
It will not grow while runningThe disk hangs off an IDE controllerPower the VM off, or move the disk to SCSI/NVMe

In the ticket: VM, delta found, origin (backup proxy), consolidation, extension and the final size seen from the OS. And a note to the backup team so that Monday's snapshot report also looks for VMs with ConsolidationNeeded.
