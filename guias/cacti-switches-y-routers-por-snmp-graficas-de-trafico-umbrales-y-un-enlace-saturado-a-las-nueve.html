Cacti: switches and routers over SNMP, traffic graphs with 64-bit counters, trees, thresholds with thold, spine, and the line that looks saturated at 9:00

Cacti 1.2 on Ubuntu: install and the wizard's warnings, adding Cisco and HP switches and routers over SNMP, interface graphs with 64-bit counters, trees, thresholds with the thold plugin, the spine poller, and how to read the WAN line that looks saturated at 9:00 (95th percentile, polling interval and counter wrap).

Level 2 · Cacti: SNMP traffic graphs · 9 min read · Updated 6 Nov 2026

What you'll get

Traffic graphs for every interface on the office switches and routers, arranged in a tree by site, with an email alert when the Internet line crosses a threshold. And, when someone says "the line is saturated at nine", being able to read the graph: whether it really is at the limit, whether it is a five-minute peak, or whether the graph lies because the counter wrapped.

Before you start

  • The version: Cacti 1.2 (the stable branch; Ubuntu 24.04 ships a 1.2.2x in its packages). 1.3 is in development; do not run it in production.
  • An Ubuntu Server 24.04 with 2 vCPU and 4 GB of RAM is enough for a couple of hundred interfaces.
  • SNMP enabled on the devices, preferably v3 (a user with authentication and encryption) or else v2c with a read-only community limited by ACL to Cacti's IP. 161/UDP open from the Cacti server.
  • The contracted speed of each WAN line (without it you will not know what "saturated" means).

1. Install Cacti and spine

The package installs Apache, PHP, MariaDB (creating the database with dbconfig-common) and the scheduled task /etc/cron.d/cacti, which runs the poller every 5 minutes. Log in at http://cacti01.contoso.local/cacti as admin and the wizard checks the system. What it usually flags red:

  • MariaDB: collation-server = utf8mb4_unicode_ci, character-set-server = utf8mb4, and sizes for max_heap_table_size, tmp_table_size, join_buffer_size and innodb_buffer_pool_size according to RAM. They go in /etc/mysql/mariadb.conf.d/50-server.cnf, with a MariaDB restart.
  • PHP: memory_limit (at least 400M), max_execution_time (60) and date.timezone = Europe/Madrid, in both /etc/php/8.3/apache2/php.ini and /etc/php/8.3/cli/php.ini. The poller uses the command-line one.
  • Time zones in MariaDB: the last two commands above.

Do not carry on with red warnings: the wizard lets you, but those settings end up as graphs with gaps.

2. SNMP on the devices and a test from Cacti

On a Cisco switch, read-only SNMPv3 limited to Cacti's IP:

On HP/Aruba (ArubaOS-Switch) the equivalent is snmpv3 enable, snmpv3 user cacti auth sha ... priv aes ... and snmpv3 group managerpriv user cacti sec-model ver3. Before touching Cacti, test from the server:

The first is the device name (sysName); the second, ifHCInOctets, the 64-bit counters of bytes received per interface. If snmpget gives Timeout, it is the ACL, the firewall or the keys; if it answers but the second returns nothing, the device has no 64-bit counters or only speaks v1.

3. Add a device and its graphs

For HP or generic devices, the Generic SNMP Device template. On saving, Cacti shows the SNMP response at the top (name, location, uptime): if it is red, go back to step 2.

Then Create Graphs for this Device. Under the SNMP - Interface Statistics query there is a line per interface with its name, alias (the port description), speed and status:

  • Always 64-bit. A 32-bit byte counter wraps at about 4.3 billion: at 1 Gb/s that happens every 34 seconds, long before the poller comes round. With 64 bits it never wraps in practice.
  • Graph the links that matter (WAN, uplinks, servers), not all 48 ports of every floor switch.
  • Put a description on switch ports: the graph's alias comes from it.

4. Trees

Loose graphs are never found. Console › Management › Trees › Add: a Network tree with a branch per site (Madrid, Valencia) and the devices inside. Drag them from the list on the right and choose to sort by name on the branch. On the Graphs tab, the tree shows every graph for a device or a site at once.

5. Thresholds with thold

The thold plugin alerts when a value crosses a limit. Install it from its official GitHub repository (Cacti/plugin_thold), version 1.8, the one for Cacti's 1.2 branch, into the plugins folder:

In Console › Configuration › Plugins, Install and Enable thold. Outgoing mail is set in Console › Configuration › Settings › Mail/Reporting/DNS (SMTP server and sender), with a test email before you go on.

  • The graph stores bytes; the Turn Bytes into Bits CDEF compares in bits, like the contracted speed. Here, 400 Mb/s on a 500 line.
  • Breach Duration avoids alerts from a one-sample spike: it only fires if it stays above for 15 minutes.
  • The device status check (Downed Device Detection) already alerts if a switch stops answering; thold is for values.

6. The poller: spine and interval

The default poller is cmd.php (PHP, one by one). spine, written in C and multithreaded, is faster:

Spine reads the database settings from /etc/cacti/spine.conf. In Console › Utilities › View Cacti Log each cycle leaves a line SYSTEM STATS: Time:12.4 Method:spine Processes:1 Threads:4 Hosts:38 HostsPerProcess:38 DataSources:412 RRDsProcessed:203. If Time gets close to 300 seconds, the poller is not finishing in time and gaps appear.

Dropping to 1-minute polling gives finer graphs, but means changing Poller Interval, the line in /etc/cron.d/cacti and the data profile (Console › Presets › Data Profiles) together. It only affects new data sources: existing RRDs keep their 5-minute step.

7. The ticket: "the Internet line is saturated every morning at nine"

Management complains everything is slow first thing. The Madrid line is 500 Mb/s symmetric. The daily graph for WAN-Fibra-Madrid shows a peak every morning, and someone is already talking about upgrading the line. Before asking for a quote, three questions for the graph.

What does each point measure? With 5-minute polling, each point is the average of those 5 minutes. A 380 Mb/s average can hide 2 minutes at 500 Mb/s (saturated) and 3 at 300. In the weekly or monthly view each point is the average of 30 minutes or 2 hours and the peak flattens further. For the rush hour, look at the daily graph or zoom by dragging across the area; the legend shows Current, Average and Maximum.

Is it real, or a counter wrapping? Signs the graph is lying:

  • Peaks above the interface speed (900 Mb/s on a 500 line or on a lightly used 1 Gb/s port), or gaps just after them.
  • The graph is 32-bit (In/Out Bits without 64-bit). Check the graph template and, if so, create it again with 64 bits: the old one cannot be fixed.
  • Spine took more than 300 seconds that morning (View Cacti Log): a lost cycle puts two samples together and a jump.

Cacti discards values above the data source's maximum (the interface speed), which is why a wrapping counter more often shows as a gap than as an impossible peak.

How long is it saturated for? That is where the 95th percentile helps: sort every sample of the month and discard the top 5%. In a 30-day month, 5% is about 36 hours.

  • If the line is at the limit from 9:00 to 9:30 every working day, that is about 10 hours a month: it falls inside the discarded 5% and the 95th percentile comes out low (say, 210 Mb/s). It is a concentrated peak, not an undersized line.
  • If the 95th percentile is close to 500 Mb/s, the line is tight much of the time and upgrading makes sense.

The Interface - Traffic (bits/sec, 95th Percentile) graph (another template on the same SNMP query) draws the percentile line over the traffic.

In the Madrid case: real traffic (64-bit, no gaps), flat at 495 Mb/s from 8:55 to 9:25, and a 95th percentile of 210 Mb/s. At that time of day the cause is usually something that starts with the computers: Windows or Office updates downloaded by every desktop, OneDrive syncing after the weekend, overlapping backups. The firewall or each floor uplink's graph shows which devices and destinations. The fix is usually to stagger or cache those downloads (Delivery Optimization, a maintenance window, QoS for calls), not to upgrade the line.

In the ticket: the graph with the peak zoomed in, the month's 95th percentile, the cause and the recommendation.
