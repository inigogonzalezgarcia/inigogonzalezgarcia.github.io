Dell iDRAC and HPE iLO: automating with Redfish, racadm and iLOrest, inventory and firmware across many servers, an ISO through virtual media, AD sign-in and a 401 with certificate errors

The Redfish API on both vendors, an inventory of model, serial, BIOS, firmware and health across dozens of servers with PowerShell 7 and a CSV, the basics of racadm and iLOrest, mounting an ISO through virtual media and booting from it remotely, Active Directory sign-in on the controllers, and the script that returns 401 and certificate errors.

Level 2 · Dell iDRAC and HPE iLO · 11 min read · Updated 6 Nov 2026

What you'll get

No more going controller by controller. With the Redfish API, which iDRAC9 and iLO 5 and 6 speak, a script pulls the model, serial, BIOS, firmware and health of every server into a CSV in a minute, and mounting an ISO to reinstall a server at another site is a request, not a trip. The out-of-band management with iDRAC and iLO guide covers the network, users and console; this one is the automation part.

Before you start

  • The jump host with access to the management VLAN over 443, PowerShell 7 (the script uses -Parallel, -Authentication and -ResponseHeadersVariable, which don't exist in 5.1), curl and jq.
  • An account for the scripts with the minimum role: read-only for inventory (on iDRAC, the Login privilege; on iLO, no configuration privileges). A different one, with more rights, for virtual media.
  • A CSV with the servers and the DNS name of their controller: D:\Scripts\oob.csv with columns Server,Oob.
  • Internal CA certificates on the controllers (section 7), or accept that for the first few days you will see certificate errors.

1. Redfish in five minutes

Redfish is a REST API with JSON. Everything hangs off /redfish/v1/ and collections have Members with links (@odata.id) to each item.

ResourceDell iDRAC9HPE iLO 5/6What it holds
System/redfish/v1/Systems/System.Embedded.1/redfish/v1/Systems/1Model, serial, BIOS, power, health, memory, CPU
Manager/redfish/v1/Managers/iDRAC.Embedded.1/redfish/v1/Managers/1iDRAC or iLO firmware, network, virtual media
Chassis/redfish/v1/Chassis/System.Embedded.1/redfish/v1/Chassis/1Power supplies, fans, temperatures
Firmware/redfish/v1/UpdateService/FirmwareInventorysameVersion of each component

For the script to work on both without asking the vendor, don't hard-code the paths: request the collection (/redfish/v1/Systems) and follow the first Members entry.

For many calls to the same server, a session is better than the user and password on every request: a POST to /redfish/v1/SessionService/Sessions returns the X-Auth-Token header, which is used on the following calls and removed at the end with a DELETE on the session. Sessions expire through inactivity (30 minutes by default on iDRAC) and there is a maximum per controller: a script that doesn't close them ends up locking everyone else out of a session.

2. Inventory of every server with PowerShell 7

  • On Dell, the service tag comes in SKU; on HPE, the serial number in SerialNumber. That is why the CSV carries both.
  • HealthRollup summarises the state of the whole server; if it isn't there, Health. Warning or Critical means there is something to look at in the controller's log.
  • -ThrottleLimit 10: ten controllers at a time. They are small devices; a hundred simultaneous requests to the same one don't do it any good.
  • Servers with an error are shown on screen and in the CSV, with the reason. Section 7 explains the two that come up most.

3. Firmware versions

For one specific server, with curl and jq:

  • On iDRAC each component appears twice: Installed-… (what is running now) and Previous-… (the earlier version, for rolling back). The filter keeps the installed one.
  • On iLO, the Id values are numbers and there is no previous version in the list: walk all the Members.
  • Single quotes around the URL: without them, the shell interprets $expand.

Put into the script from section 2, you get a CSV of server, component and version. Compare it with the baseline you have approved (OpenManage Enterprise, OneView or a spreadsheet) and you have the list of who has fallen behind.

4. racadm and iLOrest: the basics

Each vendor's command-line tool speaks Redfish underneath and saves writing JSON:

  • Remote racadm with -p leaves the password in the shell history: in scripts, read it from a secrets store and don't write it in the code.
  • ilorest login opens a session that lasts until logout; don't forget it in a script.
  • rawget (and rawpatch, rawpost) are for whatever the tool has no command of its own for: it is plain Redfish.

5. An ISO through virtual media to reinstall remotely

The ISO is served from an internal web server on the management network (http://10.10.90.50/iso/). Three steps, the same on both vendors except for the path:

  1. See which virtual drive there is and where: GET the controller's VirtualMedia collection (/redfish/v1/Managers/iDRAC.Embedded.1/VirtualMedia on iDRAC; on recent iDRAC9 firmware it is also under /redfish/v1/Systems/System.Embedded.1/VirtualMedia; /redfish/v1/Managers/1/VirtualMedia on iLO, where the CD/DVD is 2).
  2. Insert the ISO with the VirtualMedia.InsertMedia action.
  3. One-time boot from the CD and restart.
  • On iDRAC, the InsertMedia body also carries Inserted = $true and WriteProtected = $true, and the paths are the ones in the table in section 1.
  • With iLOrest it is one command: ilorest virtualmedia 2 http://10.10.90.50/iso/ubuntu-24.04-live-server-amd64.iso --bootnextreset followed by ilorest reboot.
  • Remember the licence: virtual media needs iDRAC Enterprise or Datacenter, or iLO Advanced.
  • Open the virtual console to see it boot from the ISO and follow the install. When it is done, eject the ISO (VirtualMedia.EjectMedia): if it stays mounted, the next restart may go back to the installer.

ForceRestart restarts without shutting down the operating system. Use it only on a server already out of service, which is the case for a reinstall; for anything else, GracefulRestart.

6. Active Directory sign-in

With directory users, a leaver in AD loses access to every controller and the log says who signed in, not root. On iDRAC9, with the standard schema and one AD group per role:

  • sslcertupload -t 2 uploads the certificate of the CA that signed the domain controllers' certificates: with validation on, the iDRAC only talks LDAPS to a trusted domain controller.
  • 0x1ff is administrator; a second group (ADGroup.2) with 0x1 (Login only) for the inventory account.
  • In the web UI, iDRAC Settings › Users › Directory Services › Microsoft Active Directory, with the Test Settings button, which tests with a real user and tells you which step fails.

On iLO, under Security › Directory: Use Directory Default Schema, the LDAP server (dc01.contoso.local, port 636), the user contexts (OU=Users,DC=contoso,DC=local) and, in the iLO's directory groups, the DN of GG-OOB-Admins with its privileges. It also has its own settings test.

Keep one local emergency account per controller, with its password in the team's password manager: if AD doesn't answer, it is the only way in.

7. The ticket: "the inventory script gives 401 and certificate errors"

Monday, 9:00. The inventory of 42 servers ends with 35 good lines and 7 errors:

The 401s. The controller received the request and doesn't accept the user. In order:

CauseHow it showsFix
The controller has no AD configured (or no licence for it)The local emergency user does get inConfigure the directory as in section 6, or a local read-only account for inventory
User formatCONTOSO\svc-redfish-ro fails and svc-redfish-ro@contoso.local gets inUse the UPN format in every script
The account isn't in the group with a roleTest Settings authenticates but assigns no privilegeAdd it to the read-only group
Password with special characters in bashcurl -u user:pa$$ fails and PowerShell worksSingle quotes, or let curl prompt for it
Account locked in ADIt worked yesterday and fails on all of them todayGet-ADUser svc-redfish-ro -Properties LockedOut

Here it was four HPE servers from last year's expansion without the Advanced licence: they have no directory authentication. A local read-only account is created on them for inventory and the licence is requested.

A script that retries with the wrong password against 40 controllers means 40 failed attempts in AD within seconds: the account locks and every script that uses it loses access. On a 401, the script records the error and moves on to the next server; it never retries.

The certificate errors. The full text is in the inner exception ($_.Exception.InnerException.Message): The remote certificate is invalid because of errors in the certificate chain: UntrustedRoot. With curl: SSL certificate problem: self-signed certificate. The three servers had a motherboard replacement this year, and the new controller came with its factory self-signed certificate.

The fix is to issue the certificate, not to skip the check:

  • The certificate comes from the internal CA with a web server template and the DNS name in the SAN. If the script calls by IP and the certificate has the name, the error will be RemoteCertificateNameMismatch: always call by name.
  • On iLO, the same from the SSL certificate section under Security: generate the CSR, sign it and paste the certificate. The iLO restarts on its own.
  • -SkipCertificateCheck (PowerShell 7) or curl -k get you through the first day, never as the fix: the script sends a password to whoever answers on that IP.

To stop it happening again, the motherboard replacement procedure includes "controller certificate", and the weekly inventory adds a column with the expiry date of each controller's certificate.
