pfSense as the office firewall: installation, interfaces and VLANs, aliases and least-privilege rules, NAT, DHCP and DNS, and a published service that cannot be reached from outside

pfSense CE from scratch in an office: installation and wizard, WAN, LAN and VLANs, aliases and rules that allow only what is needed, outbound NAT and port forwarding, DHCP with reservations, the DNS Resolver with the company domain, packages chosen with care and a published portal that does not answer from outside.

Level 3 · pfSense: office firewall · 8 min read · Updated 6 Nov 2026

Rather practise it?Solve the simulated ticket "The published server cannot be reached from outside" in SysAdmin Desks ↗

What you'll get

A pfSense firewall that splits the office into networks that make sense (servers, users, printers, management), only lets through between them what is needed, gets to the internet with NAT, hands out addresses and resolves names, and publishes one service to the outside. And the method for when that service "can't be reached from home".

Before you start

  • pfSense CE 2.8 on a box with at least two network cards (preferably Intel, igc/ix) or on a virtual machine with two adapters. The CE installer is the Netgate Installer: it needs internet access during installation because it downloads the release on the spot.
  • The address plan. In this guide: VLAN 10 servers 10.20.10.0/24, VLAN 20 users 10.20.20.0/24, VLAN 30 printers 10.20.30.0/24, VLAN 99 management 10.20.99.0/24, domain contoso.local with domain controllers on 10.20.10.10 and 10.20.10.11.
  • A managed switch with the VLANs created and a trunk to the firewall's LAN port.
  • If you come from FortiGate, the FortiGate guide tells the same concepts with different names.

1. Installation and first access

  1. Boot the installer, choose ZFS (mirrored, with two disks) and let it download and install the stable release.
  2. At the console, option 1) Assign Interfaces: igc0 as WAN, igc1 as LAN. No VLANs yet (they are created from the web UI).
  3. Option 2) Set interface(s) IP address if the LAN should not be the factory 192.168.1.1/24. Here: 10.20.99.1/24, the management network.
  4. From a laptop on the LAN, https://10.20.99.1 with admin / pfsense. The wizard asks for a hostname (fw-oficina), domain (contoso.local), time zone and the new admin password.

Then, in System › Advanced › Admin Access: HTTPS protocol, and leave the anti-lockout rule on until you have your own rule allowing management from VLAN 99. Better than admin, named accounts in System › User Manager.

2. Interfaces and VLANs

Repeat for 10, 30 and 99. Then, in Interfaces › Assignments, add each VLAN as an interface, open it, tick Enable, give it a name (SERVIDORES, USUARIOS, IMPRESORAS, GESTION) and a Static IPv4 (10.20.20.1/24...). The original LAN stays as the management network or unused.

On the WAN, pfSense comes with Block private networks and loopback addresses and Block bogon networks ticked: they block inbound traffic from addresses that should never come from the internet. Leave them that way unless the WAN sits on a private ISP network from which you need to receive something.

3. Aliases and least-privilege rules

Aliases give names to groups of IPs and ports; rules read themselves and a change is made in one place.

How pfSense evaluates:

  • Rules apply on the interface where the traffic comes in: what leaves the users is filtered on the USUARIOS tab.
  • Top to bottom, the first match wins. Floating rules are evaluated before.
  • Whatever matches nothing is blocked. A new VLAN with no rules lets nothing through.

The USUARIOS rules, in this order:

ActionSourceDestinationPortWhat for
PassUSUARIOS netDCSPUERTOS_AD (TCP/UDP)Sign-in, DNS and GPO
PassUSUARIOS netSRV_ERP443The business application
PassUSUARIOS netIMPRESORAS net9100, 443Printing and the web console

PassUSUARIOS netanyanyInternet
  • The PRIVADAS block before the "to the internet" rule is what stops a user PC from reaching the management VLAN.
  • Tick Log on the blocks: it is what you will look at in Status › System Logs › Firewall when someone says "it won't let me".
  • Every rule with a description saying who asked for it and why.

4. Outbound NAT and port forwarding

  • Outbound: in Firewall › NAT › Outbound, Automatic mode creates the rules for every internal network. Switch to Hybrid only if you need something special (a specific public IP for a server, static port for a phone system) and add those rules at the top.
  • Inbound: publishing the customer portal running on 10.20.10.20:

The associated rule appears under Firewall › Rules › WAN. If only a few use the service (a supplier, another site), restrict the source with an alias on that rule. And the published server is better in its own VLAN (a DMZ) than next to the domain controllers.

5. DHCP and the DNS Resolver

  • DHCP: in Services › DHCP Server, one tab per interface. Range, gateway and, on a network with Active Directory, DNS servers = the domain controllers. Reservations under Static Mappings: MAC, IP and name. ISC DHCP is deprecated in pfSense; in System › Advanced › Networking, Server Backend: Kea DHCP is the engine that keeps evolving.
  • DNS Resolver (Unbound, on by default) in Services › DNS Resolver: it listens on the internal interfaces. For pfSense and the non-domain networks to resolve contoso.local, a Domain Override for contoso.local pointing to 10.20.10.10. Host Overrides are for the split DNS in step 7.
  • In System › General Setup, the upstream DNS servers and the box to not use the ISP's if you want consistent resolution.

6. Packages, chosen with care

System › Package Manager › Available Packages. The most useful in an office:

  • pfBlockerNG: lists of malicious IPs and domains.
  • acme: Let's Encrypt certificates for the web UI itself or a proxy.
  • openvpn-client-export and WireGuard: the VPN (pfSense remote access guide).
  • Zabbix Agent, or SNMP under Services › SNMP, for monitoring.

Every package is one more thing to update and one more thing that can break in a version upgrade: install what you will use and record it in the firewall's documentation.

7. The ticket: "the customer portal cannot be reached from outside"

Monday, 9:00. After the ISP router was swapped on Friday, customers cannot get into https://portal.contoso.example. From the office, by IP, it works.

  1. Does the traffic reach the firewall? Diagnostics › Packet Capture: WAN interface, port 443, and a test from a phone on mobile data. Not a single packet. And in Status › Interfaces, the WAN has 192.168.1.2: a private IP.
  2. The ISP router is doing NAT in front. The new router did not come in bridge mode: the public IP lives on it and inbound connections die there. Two ways out: ask the ISP for bridge mode (pfSense gets the public IP) or, failing that, forward 443 on the ISP router to 192.168.1.2 or set it as the DMZ host. If the ISP router's WAN IP is in 100.64.0.0/10, it is CGNAT: with no public IP nothing can be published; one has to be ordered.
  3. If packets do arrive but nothing answers, rule order: in Status › System Logs › Firewall, a block on WAN towards 10.20.10.20:443 from a pfBlockerNG rule or a Block rule placed above the associated one. Move the pfBlockerNG rule or add an exception for the portal. If the log shows nothing, check that the forward has its associated rule and that the Destination is WAN address.
  4. If the firewall forwards but the server does not answer: in Diagnostics › States, the state stays at SYN_SENT:CLOSED. The server's gateway is not the firewall, or the server's Windows firewall lacks the 443 rule.
  5. "From the office, by name, it doesn't load": that is a different problem, NAT reflection. Inside, portal.contoso.example resolves to the public IP and pfSense, by default, does not hairpin it back in. The clean fix is split DNS: a Host Override in the DNS Resolver (or a record in Active Directory DNS) for portal.contoso.example pointing to 10.20.10.20. The alternative is System › Advanced › Firewall & NAT › NAT Reflection mode for port forwards: Pure NAT.

In the ticket: where it was being cut (ISP router in router mode), the change made, the test from outside (phone on mobile data) and from inside by name.
