Zabbix: Cisco and HP/Aruba switches over SNMPv2c and v3, network discovery, interface LLD, link down, errors and bandwidth, and a switch showing "no data"

SNMPv3 with an ACL on a Cisco and an HP/Aruba, the snmpwalk test before touching Zabbix, the host SNMP interface and official templates, network discovery rules with an action, interface discovery filtered by macros, link down only on the ports that matter, errors, saturation and a switch with a red SNMP icon.

Level 3 · Zabbix: server, agents and templates · 11 min read · Updated 6 Nov 2026

What you'll get

The office and server room switches inside Zabbix with the same quality as the servers: SNMPv3 with read access limited to the monitoring IP, automatic onboarding with a discovery rule, interfaces discovered on their own and link-down alerts only on trunks, uplinks and server ports, not on every desk that switches off at seven. And when a switch shows a red SNMP icon and no data, knowing whether it is the network, the ACL or the credentials.

Before you start

  • The Zabbix 7.0 LTS server from the server, agent 2 and templates guide, and the IP that will run the queries: the server's (10.10.20.15) or the branch proxy's, if the switch sits behind one.
  • Configuration access to the switches. The basics for each vendor (configuration mode, configuration backup) are in Cisco: first commands and HP/Aruba switches.
  • Ports: the server or proxy queries the switch on 161/UDP. Traps (162/UDP) are a different mechanism and are not needed for this guide.
  • The snmp package (and optionally snmp-mibs-downloader) on the server and proxies, to test with snmpwalk.
  • An authentication password and a privacy password for SNMPv3, 12 characters or more, stored in the team's password manager.

1. SNMP on a Cisco IOS / IOS XE

SNMPv3 with authentication and encryption (authPriv), read-only and limited by an ACL. A v2c community only if some device does not support v3, and also with an ACL:

  • 10.10.20.15 is the Zabbix server and 10.20.0.5 the Valencia proxy: every machine that will query the switch must be in the ACL.
  • The v3 user does not appear in show running-config: check it with show snmp user. When you copy the configuration to another switch, the user has to be created by hand.
  • If v2c is needed: snmp-server community Nw7-ro-Contoso RO ACL-SNMP-ZABBIX. Never public or private, and never RW.
  • snmp-server location and contact end up in the Zabbix inventory: fill them in properly once.

2. SNMP on an HP/Aruba running AOS-S (2530, 2930F, 3810)

  • snmpv3 enable asks interactively whether to create the initial user: create it with a long password or remove it afterwards with no snmpv3 user initial.
  • The operatorauth group is read-only. The manager groups allow writes: they are not used for monitoring.
  • To limit who can query, ip authorized-managers restricts switch management (web, SSH and SNMP) to the listed IPs. If it is already in place, add the Zabbix server and proxies, or SNMP will stop answering without any error.
  • AOS-CX switches (6000, 6100, 6300) use a different syntax (snmp-server vrf mgmt, snmpv3 user ... auth sha auth-pass plaintext ... priv aes priv-pass plaintext ...) and SNMP goes through the management VRF if the management cable is there.

3. Test from Zabbix before creating anything

The query runs from the machine that will do the checks (server or proxy). If snmpwalk does not work, Zabbix will not either:

  • 1.3.6.1.2.1.1.5.0 is sysName and 1.3.6.1.2.1.1.1.0 is sysDescr. 1.3.6.1.2.1.31.1.1.1.1 is the ifName table, the one interface discovery will use.
  • Single quotes stop bash from interpreting the ! in the password.

4. The SNMP host and the official templates

Credentials go in macros, not typed into every host. In Administration › Macros (or on the host group):

  • {$SNMP_COMMUNITY} = the v2c community, for the devices that need it.
  • {$SNMPV3_AUTH} and {$SNMPV3_PRIV} as Secret text, with the two v3 passwords.

  • The templates bring CPU, memory, fans, power supplies and temperature when the vendor publishes them, plus interface discovery.
  • Use combined requests bundles several OIDs in one query. Some old devices do not support it and answer only partly: if an old switch returns odd data, unticking it is the first thing to try.
  • With a proxy at the branch, Monitored by: Proxy and the proxy chosen: the switch is queried from there and the ACL must allow its IP.

5. Network discovery rules

So that 40 switches are not created by hand, a rule sweeps the management subnet and an action creates what it finds. In Data collection › Discovery › Create discovery rule:

The action, in Alerts › Actions › Discovery actions, decides what is created and with what:

  • A second identical action with Received value contains Aruba (or whatever text your sysDescr returns) and the HP Enterprise Switch by SNMP template.
  • The host name comes from sysName: if the switches are still called Switch from the factory, discovery creates hosts with duplicate names. First the name on each device, then the rule.
  • An interval of 1 h is enough: the rule does not monitor anything, it only finds. A short interval over several /24s loads the server for no reason.
  • Monitoring › Discovery shows what the rule found and which service answered on each IP.

6. Interfaces: what to discover and what alerts

The template's discovery rule (Network interfaces discovery) creates, for each port, inbound and outbound traffic, errors, discards, speed and status. Its triggers:

  • Link down: the operational status goes down after having been up. It does not fire on ports that have never come up. It requires manual close.
  • High error rate: errors per second above {$IF.ERRORS.WARN} (2 by default) for 5 minutes.
  • High bandwidth usage: 15-minute average above {$IF.UTIL.MAX} (90 %) of the port speed.
  • Ethernet has changed to lower speed than it was before: the server port that negotiates at 100 Mb instead of 1 Gb.

On an access switch with 48 desks, Link down on every port is noise. It is controlled with {$IFCONTROL} and macros with context, on the host or on a template of your own for access switches:

  • {$IFCONTROL} = 0 turns off the link-down alert for the whole switch and the context turns it on only for the uplinks, the 10 Gb ports and the port-channels. The name is the ifName the device returns (Gi1/0/48 on Cisco; on AOS-S it is usually the port number, such as 48, or 1/48 in a stack).
  • Ports disabled on purpose (shutdown, adminStatus 2) are no longer discovered: they create no items and no alerts.
  • Each port is about ten items. On a 48-port switch, around 500: if the database is a concern, filter with {$NET.IF.IFALIAS.MATCHES} to discover only ports with a description (the ones the team has documented).
  • For the bandwidth trigger on a 600 Mb internet circuit plugged into a 1 Gb port, the percentage misleads: a trigger of your own on the traffic item with the circuit's value (> 540M).

Input errors on a single port are usually a cable or a patch lead. Before changing anything, show interfaces Gi1/0/12 counters errors on Cisco or show interfaces 12 on AOS-S, and the item's graph to see since when.

7. The ticket: "the floor 2 switch shows no data"

Thursday, 9:40. Monitoring › Problems shows SW-PL2-01: No SNMP data collection and in Monitoring › Hosts the switch's SNMP icon is red. Users on floor 2 are working normally: the switch works, what fails is the query. The error, when hovering over the icon:

  1. Does it reach? An SNMP timeout does not distinguish between "does not reach", "the ACL drops me" and "the community is wrong": with v2c, the switch silently drops a community it does not know. First, ping from the machine that queries (the server, or the proxy if the host is Monitored by: Proxy). If it answers, the network reaches.
  2. Repeat the query by hand from that same machine, with the host's exact settings:

It answers with v3 and not with v2c: the host is set up with v2c and the switch no longer has that community.

  1. What changed: last week's change record says the floor switches were moved to SNMPv3 and the community removed, but the Zabbix hosts still have a v2c interface. The host interface is changed to SNMPv3 (or better, in the access-switch template of your own, for all of them at once).
  2. The other usual causes, by message:
  • Timeout from the proxy but not from the server: the proxy's IP is missing from the ACL (show access-lists ACL-SNMP-ZABBIX shows the deny counters) or from ip authorized-managers.
  • Authentication failure (incorrect password, community or key) or Unknown user name: the v3 password or user is mistyped, or the protocol (SHA versus SHA256, AES128 versus AES256) does not match the switch's.
  • No Such Object available on this agent at this OID on some items: the switch's SNMP view does not include that branch, or the model does not publish that value. The host stays available; those items become not supported.
  • Only some items fail on an old switch: untick Use combined requests or lower Max repetition count.
  1. Check: Execute now on one of the switch's items, the SNMP icon goes green again and Latest data shows traffic from the last few minutes. The problem closes on its own.

In the ticket: the exact error, the snmpget test from the same source as Zabbix, the cause (move to v3 without updating the interface) and the check.

So it does not happen again, the SNMP version and credentials live in a template or in group macros, not on each host: the next credentials change is one edit, not forty.
