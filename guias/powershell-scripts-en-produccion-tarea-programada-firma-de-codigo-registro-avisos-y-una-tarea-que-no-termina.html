Guides · Level 2

PowerShell in production: scheduled tasks with a gMSA, code signing with the internal CA, logging with Start-Transcript, alerts through Graph or Teams and a task stuck on “Running”

The template for a script you can leave on its own: exit codes, a transcript with retention, signing with an internal CA certificate and AllSigned by GPO, the scheduled task and its settings, alerts by email with Send-MgUserMail or to a Teams channel, and the task that says “Running” while doing nothing or ends with 0x1.

Level 2 · PowerShell · 10 min read · Updated 6 Nov 2026

What you'll get

Scripts that run at night on the servers and can be trusted: only what the team has reviewed and signed runs, every run leaves a log, a failure reaches the team channel before someone finds it at 9:00, and the scheduled task never hangs for three days. The example is a nightly backup of the GPOs, but the template works for any script.

Before you start

  • A management server, here srv-mgmt01, and a gMSA for the script (CONTOSO\gmsa-gpobackup$). How to create and install it is in the service accounts and gMSA guide.
  • An internal CA (AD CS) with a code signing template published to the group of people who sign.
  • The scripts in a repository, as in the Git for the team's scripts guide: what has passed review is what gets signed.
  • For alerts: an app registration in Entra ID with a certificate, or a Teams workflow with a webhook. The basics of Graph are in first queries with Microsoft Graph.

1. The script template

  • exit $code: 0 if everything went well, 1 if not. It is what the scheduled task and monitoring see as Last Run Result.
  • Stop and try/catch: any error goes to the catch, an alert is sent and the script exits with 1. Without Stop, many errors just print in red and the script carries on.
  • Transcript with retention: one file per run, and those older than 30 days are deleted in the finally, which runs even on error. Without retention, the logs folder ends up with thousands of files.
  • A common-sense check (fewer than 5 GPOs is impossible in this domain): it turns an empty result into a visible error.
  • Nothing interactive: no Read-Host, no Get-Credential, no Remove-Item without -Recurse on a folder with content, which asks for confirmation. In a task, a question is a hung script.

2. Signing with the internal CA

Whoever signs requests a certificate from the code signing template (in certmgr.msc › Personal › Certificates › All Tasks › Request New Certificate). The private key is non-exportable or on a smart card: whoever holds that key can make any script run on every server.

  • The signature goes in a comment block at the end of the file. Any change afterwards, even a space, invalidates it (HashMismatch).
  • If you have access to a timestamping service (RFC 3161), add -TimestampServer: with a timestamp the signature stays valid when the certificate expires; without one, everything has to be re-signed when the certificate expires.
  • Sign after review and from the repository version. If Git changes line endings on clone, the signature stops being valid on the server: set *.ps1 text eol=crlf in .gitattributes.

3. AllSigned by GPO and trusted publishers

In a GPO linked to the servers OU:

  • The company root CA is already trusted on domain computers. What's missing is the publisher: without the certificate in Trusted Publishers, PowerShell asks "Do you want to run software from this untrusted publisher?" and, in a task, nobody is there to answer.
  • The policy set by GPO (MachinePolicy scope) overrides -ExecutionPolicy Bypass on the command line. Check it with Get-ExecutionPolicy -List.
  • The execution policy isn't a barrier against an attacker; what it brings here is that only code reviewed and signed by a named person runs in production.

4. The scheduled task

  • -NonInteractive: if anything asks a question, it fails instead of waiting forever.
  • -ExecutionTimeLimit: the default is 72 hours. Set something close to how long it really takes, with a margin. When it is exceeded, Task Scheduler stops the task.
  • -MultipleInstances IgnoreNew: if yesterday's run is still going, today's doesn't start (event 322). That way you see the problem instead of piling up processes.
  • -StartWhenAvailable: if the server was off at 2:00, the task runs when it starts.
  • Task history is off by default; wevtutil turns it on (the same as Enable All Tasks History). Without it, the ticket in section 6 is investigated blind.
  • The gMSA needs Log on as a batch job, Modify on D:\Scripts\Logs and on the destination, and Read on D:\Scripts. Nobody except administrators writes to D:\Scripts.

5. Alerting the team: email through Graph or a Teams channel

Send-MailMessage is marked as obsolete. Two alternatives, in D:\Scripts\Common\Alerts.ps1 (signed too):

Email through Microsoft Graph. An app registration with the Mail.Send application permission and certificate authentication. Application Mail.Send allows sending as any mailbox: limit it to the it-alerts@contoso.com mailbox with Exchange Online RBAC for Applications (which replaces application access policies). The certificate goes in the computer store and the gMSA gets read permission on its private key (certlm.msc › the certificate › All Tasks › Manage Private Keys). The Microsoft.Graph.Authentication and Microsoft.Graph.Users.Actions modules are installed with -Scope AllUsers: the gMSA has no profile in which to find the ones in your user profile.

The function's own try/catch is deliberate: if the alert fails, it is recorded in the transcript, but it doesn't hide the original error or change the exit code.

A Teams channel. A Workflows flow on the channel, with the Send webhook alerts to a channel template (the old Office 365 webhook connectors have been retired). The URL it generates is a secret: it goes in a file only the gMSA can read, not in the script.

Sending the bytes as UTF-8 stops Windows PowerShell 5.1 from turning accented characters into garbage in the message.

6. The ticket: "the task has been Running since 2:00 and hasn't done anything"

Thursday, 9:10. Nobody got an alert, but there is no folder for today in \\srv-files01\Backups$\GPO. Task Scheduler shows Backup GPO as Running since 2:00.

267009 is 0x41301: the task is currently running. The process exists and has no -NonInteractive: someone recreated the task by hand from the console on Tuesday, without the settings from section 4, and the limit went back to 72 hours. Today's transcript ends on the line that explains it: Tuesday's change added a Remove-Item of the old backups without -Recurse, which asks The item has children… Do you want to continue?. The script has been waiting seven hours for an answer.

The task is stopped (Stop-ScheduledTask), the script is fixed in the repository, signed and copied. When it is run again, it ends in one second with 0x1. And this time there is no transcript: the error happens before Start-Transcript. To see what the task doesn't show, run the same thing it runs:

Someone had tweaked a path with Notepad on the server after copying it. With AllSigned, the script never loads and powershell.exe exits with 1. The signed version is copied again and the task ends with 0.

The codes that come up most:

ResultMeaningWhere to look
0x0powershell.exe ended with 0Whether the script did what it should: the transcript
0x1The script exited with 1 or never loadedThe transcript; if there isn't one, run it by hand as above
0x41301Still runningA process waiting on a question or on a resource that doesn't answer
0x41306The task was terminated (by hand or by the time limit)If it matches ExecutionTimeLimit, the script takes longer than expected
0x8007010BThe start directory doesn't exist-WorkingDirectory mistyped
0x800710E0The operator or administrator has refused the requestThe account lacks Log on as a batch job or the task only runs when the user is logged on

In Event Viewer, Microsoft › Windows › TaskScheduler › Operational: 100 (started), 129 (process created, with its PID), 201 (action completed, with the code) and 102 (task completed). A 129 with no 201 is a process that is still alive.
